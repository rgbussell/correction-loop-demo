correction-loop-demo — build report

A continual-learning loop that learns from correction deltas — and can be seen refusing a bad round. Open data (VerSe 2020, CC BY-SA 4.0), MIT code. Updated 2026-09-12 · W0–W2: 2 round(s) run 17/17 tests passing

What this demo is

Production segmentation models are corrected by humans every day, and those corrections are usually thrown away. This demo builds the loop that keeps them: each round, a model meets a batch of new cases, its outputs are corrected, the correction delta becomes the training signal, and a retrained candidate is promoted only if it beats explicit null controls. The demo's job is to show the loop shape — including the round where the loop says no.

Three design commitments, made before any model exists:

  • Sequestration is a refusal, not a filter. Held-out test cases raising an error on contact with curation — never silently dropped.
  • Every promotion beats two nulls. A matched random cohort at equal N, and do-nothing. Improvement that can't beat "just add any cases" proves nothing about the selection rule.
  • One batch is poisoned on purpose (wrong-level enumeration). A loop that cannot be seen refusing a bad batch is theater.

What was done. scripts/build_partition.py scans every case directory, picks one CT series per case by a fixed preference order (CT-iso → bare → CT-ax → CT-sag), and derives each case's vertebral coverage from the reference labelmap itself (np.unique), not from metadata sidecars. Two honest findings along the way, kept in: (1) VerSe file naming is heterogeneous — verse* and GL* ids, dash and underscore series tags, and a bare-name series for a third of cases; the scanner handles all of them and skips 12 directories with no complete image+mask pair. (2) Centroid JSONs exist for only 26 of 119 directories in this mirror, which is why coverage comes from the masks. Every case's chosen series, coverage, shape and spacing is recorded in manifests/cases.json — the committed, diffable inventory the whole demo builds on.

Step 3 — The poison, declared and audited

Audit trail. manifests/poison.json records, per poisoned case: the source mask's sha256, the poisoned copy's sha256, the full label map applied, and the foreground voxel count (identical before/after — the poison relabels, never redraws). Originals are never touched; poisoned copies live outside git in data/poisoned/ and are substituted only when batch 2 "arrives". 13 cases, 189 labels shifted in total.

Step 4 — The ruler, null-tested and validated on the real poison (W1)

What was built. src/clloop/delta.py — the frozen correction-delta ruler. Per (auto, final) pair it reports three things: added path length (APL, mm — the contour a human would have to redraw, label-aware so identity errors carry their true cost; Vaassen et al. 2020), surface Dice (Nikolov et al. 2018 — deliberately label-blind, so its disagreement with APL becomes a diagnostic), and a per-level taxonomy: boundary / relabel / missing / spurious.

Why two scores that can disagree? Because their disagreement is the signature of the most dangerous failure class. An enumeration error leaves shapes perfect (surface Dice ≈ 1) while every renamed contour still needs redrawing (APL large). A single overlap score cannot see this; the pair cannot miss it.

Step 5 — The loop turns: baseline + round engine (W2)

What was built. A one-command round engine (scripts/run_round.py --round K): the incumbent model predicts the arriving batch, the frozen W1 ruler scores every correction delta on the native grid, the cohort is curated (in W2 still an accept_all stub that says so in its own record), the model retrains with a declared ~25% rehearsal mix, and the candidate is evaluated on the 24-case sequestered test set — per-region Dice for what it knows, ruler APL for what it would cost to fix. Every round writes a complete round.json: training mix, per-case deltas, evaluation, timing.

Scale honesty: a small MONAI 3-D U-Net at 3 mm isotropic, 400 iterations/round — minutes per round on one consumer GPU. The demo measures loop mechanics, not segmentation SOTA; the coarse grid is a declared choice, and the ruler still scores on the native grid.
